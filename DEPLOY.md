# Деплой и перезапуск

## Золотое правило

**`git pull` ≠ задеплоено.** Бэкенд загружается в память один раз при старте процесса и не обновится, пока процесс не перезапущен.

| Что обновляется | Как | Нужен рестарт? |
|---|---|---|
| Фронтенд (`dist/`) | читается с диска на каждый запрос | нет |
| Бэкенд (`server/**`) | загружается один раз при старте | **да** |
| Переменные окружения (`.env`) | читаются один раз при старте | **да** |

Из-за этого легко обмануться: после `git pull` фронт меняется сразу, и кажется, что деплой прошёл, — а бэкенд крутится старый.

## Прод (HostPro)

Хостинг работает на **LiteSpeed (lsnode)**, не на Passenger.

> Кнопка «Restart» в cPanel и `touch tmp/restart.txt` процесс **не перезапускают**. Проверено — не тратьте на них время.

### Поменял только фронт (html / css / js)

```bash
cd ~/townhouses-shevchenkovo
git pull
```

Затем hard-refresh страницы: `Ctrl+Shift+R`. Процесс трогать не надо.

### Поменял бэкенд (`server/**`, `.env`)

```bash
cd ~/townhouses-shevchenkovo
git pull
pkill -f "lsnode:/home/bueacjlb/townhouses-shevchenkovo"
```

После `pkill` открыть сайт — процесс поднимется сам на первом запросе. Убедиться, что PID сменились:

```bash
ps aux | grep -i node | grep -v grep
```

Если PID те же — добить `pkill` ещё раз.

### Проверка живости API

```bash
curl -s https://ВАШ_ДОМЕН/api/health     # → {"ok":true}
```

## Локальная разработка

Процессов два, и путают обычно именно их:

| Процесс | Команда | Порт | Отвечает за |
|---|---|---|---|
| Vite | `npm run dev` | 5173 | фронт с горячей перезагрузкой |
| Express | `npm run server` | 3000 | `/api/leads` → Telegram + Pipedrive |

```bash
# терминал 1 — API
npm run server

# терминал 2 — фронт
npm run dev
```

Открывать нужно адрес **Vite (:5173)**. В `vite.config.js` задан `proxy: { '/api': 'http://localhost:3000' }` — то есть Vite сам формы не отправляет, а проксирует на Express. Если запустить только `npm run dev`, сабмит формы упадёт с ошибкой соединения.

На `:3000` отдаётся собранный `dist/`, то есть старая сборка, — для разработки фронта этот адрес не подходит.

Перезапуск Express локально: `Ctrl+C`, затем `npm run server`. Если терминал потерян:

```bash
lsof -i :3000        # узнать PID
kill <PID>           # именно kill, без -9
npm run server
```

`-9` не нужен: в `server/index.js` есть обработчики `SIGTERM`/`SIGINT`, которые закрывают соединения корректно.

## Грабли

**`NODE_ENV=production` без сборки** — сервер откажется стартовать:

```
[fatal] dist/index.html не найден — выполните "npm run build" перед запуском
```

Это защита от запуска сайта без фронтенда, а не поломка. Нужен `npm run build`.

**Не использовать глобальный `fetch` в `server/**`.** На этом хостинге undici инстанциирует WASM-парсер (llhttp), который падает с `Out of memory` и роняет процесс — наружу это выглядит как 502. Для внешних запросов есть `server/lib/http.js` (`fetchWithTimeout`) на нативных модулях `http`/`https`, интерфейс совместим с fetch.
